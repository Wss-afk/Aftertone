# 歌曲重命名验收

日期：2026-11-06，Europe/Madrid。

## 行为与改动

- 歌曲行增加铅笔按钮；原歌名自动聚焦并全选，支持取消、Esc、Enter 保存。
- JSON `PATCH /api/v1/tracks/{id}` 更新歌名，成功返回 200 和歌曲信息。
- 去掉首尾空白后须为 1–255 个 Unicode 字符，中文和表情均可用；空名称、超长名称和内部控制字符返回 `400 INVALID_TITLE`，损坏或缺失 JSON 返回 `400 INVALID_REQUEST`。
- 事务中锁定所选歌曲，仅修改 title；正在删除及不存在的记录返回 404。数据库保存失败返回 `RENAME_FAILED`，提交结果不明确时提示先刷新确认。
- 仅成功后更新界面；失败保留输入供重试，保存期间禁止重复提交和关闭。忽略保存前发出的过期列表响应。
- 当前歌曲只更新播放器标题，保留同一音频元素、音源、进度及播放状态。原文件名、大小、上传时间、UUID 文件和播放顺序保持不变，无需数据库迁移。

## 实际接口与网页

使用专用 MySQL 测试库、独立音乐目录、后端 18080 和代理 15173。上传本地生成的 90 秒 432 Hz 测试音，日常歌曲未参与改名测试。

1. 直连和代理改名均返回 200。无效名称返回 400，不存在 ID 返回 404，损坏 JSON 返回 400，均包含可读错误。
2. 改名前后歌曲 ID、原文件名、音频 URL、字节数、上传时间及列表 ID 顺序一致；音频文件 SHA-256 和既有测试歌曲保持不变。
3. 网页确认空名称提示、取消编辑及原歌名自动全选。
4. 播放中保存为“夜航 · 网页保存验证 🎵”，音源一直为 `/api/v1/tracks/6/audio`，paused 一直为 false；保存前进度 17.468884 秒，保存后 17.790695 秒，播放器标题同步更新。
5. 重启测试后端，重新加载网页仍显示新歌名，能够重新播放。直连完整读取 200，代理首段读取 206、1024 字节，音频哈希不变。
6. 日常后端更新后，原有两首歌曲的元数据、微秒上传时间及音频 SHA-256 保持不变。日常页面只打开并取消编辑，没有保存对原歌曲的改动。

隔离检查脚本：`scripts/verify-track-rename.mjs prepare` → 网页保存测试歌名 → `checkpoint` → 重启隔离后端 → `verify`。需要预先准备专用测试配置和 `.local/rename-verification/rename-tone.mp3`，不使用日常端口。
