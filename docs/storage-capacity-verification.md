# 容量显示与低空间保护验收

日期：2026-11-06，Europe/Madrid。

## 行为

- 查询接口 `GET /api/v1/storage` 返回实际曲库播放文件字节数、所在磁盘总空间和可用空间、预留线及上传是否允许。
- 默认安全预留线为 5 GB，另加本次上传、转码和临时开销的工作余量。
- 过滤器在 Spring 解析 multipart 前检查空间；存储层在复制、处理及最终保存时继续检查。低空间返回 507，容量读取失败返回 503。
- 只清理本次上传的明确临时文件，不清理已有音乐。低空间不阻止查询、播放和单首删除。
- 页面在打开、上传完成或失败、删除成功、窗口重新获得焦点和手动刷新时更新容量。没有每秒或定时持续轮询。

## 自动化

后端 36 项测试、前端 20 项测试均通过，0 跳过；TypeScript 与 Vite 构建通过。新增覆盖：

- 统计实际 UUID 音频文件，排除临时文件。
- 阈值边界、每次写入的余量检查、容量读取错误。
- 低空间时尚未开始写入就拒绝；处理中空间下降时退出并清理本次文件。
- 表单解析前的过滤器拦截，读取和删除请求不受此过滤器影响。
- 页面低空间提示与上传按钮禁用、释放空间后刷新恢复、上传后更新，以及容量读取失败时播放器保持可用。
- 删除成功和窗口重新获得焦点时重新读取容量。

## 隔离实际接口测试

使用专用 MySQL 测试库、独立音乐目录、后端 18080 和 Vite 代理 15173；测试音为项目生成的短音频。

1. 将测试实例的预留线临时设为 999 TB，模拟低空间，不填充磁盘。
2. 直连和代理均返回 uploadAllowed=false；小文件及 12 MiB 生成请求均返回 `507 application/problem+json`、`INSUFFICIENT_STORAGE`。
3. 原测试音仍能读取，未知歌曲 DELETE 仍正常返回 404；记录和原音频哈希不变，multipart 暂存目录无残留。
4. 浏览器选好测试文件后，上传按钮仍禁用，播放与删除入口保持可用。
5. 将测试预留线恢复为 5 GB 后重启，直连和代理均允许上传。新增一份测试音时曲库字节数相应增加，单独删除该份测试音后恢复原值；原测试音保持不变。

测试脚本：`scripts/verify-storage-capacity.mjs low` / `normal`，仅连接测试入口。

## 日常页面

日常实例采用默认 5 GB 预留线，读取到曲库音频 14037156 字节，页面显示约 13.4 MB；磁盘可用约 641.5 GB，允许新增上传。实际文件大小总和与接口一致，加载功能前后已有记录、上传时间和音频 SHA-256 保持一致。

## 范围

低空间使用配置和模拟测试完成，没有实际写满或卸载磁盘。空余空间检查不是操作系统级配额，无法控制其他软件同时写盘；后端重复检查以减少本应用继续消耗安全余量。预留规则不会创建占位文件或锁住空间。
