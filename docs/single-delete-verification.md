# 单首删除验收

日期：2026-11-06，Europe/Madrid。

## 功能

- 每行歌曲提供独立删除按钮，确认框显示具体歌名，默认聚焦取消。
- 确认后仅删除选中的歌曲记录和对应的一个 UUID 音频文件；上传来源文件保留。
- 取消或 Esc 不发删除请求。请求期间阻止重复确认及取消。
- 删除当前曲目后停止并清空播放器；删除其他曲目不重载当前音源或进度。
- 请求失败时保留歌曲，恢复被暂时释放的播放状态和进度，并允许重试。

## 数据和文件的一致性

Flyway V2 为 tracks 增加 deleting 字段。删除先在独立事务中锁定目标记录并提交删除意图，然后验证 UUID 和实际文件路径，删除这个明确路径，最后清理数据库记录。

- 删除意图无法确认提交时不碰文件。
- 文件删除失败时恢复可见记录。
- 文件已删除但最后的数据库清理失败时，保留隐藏的待完成记录，重试或重启后完成。
- 启动时对未完成记录核对文件：文件仍在就恢复歌曲，文件已无就完成记录清理。此阶段只修改数据库，不删除任何音频文件。

## 独立 MySQL 与文件验证

使用项目专用 MySQL 测试实例 13308、新建的 `night_signal_delete_test_*` 数据库、`.local/delete-verification/music` 文件夹，以及 18080 测试后端；不对日常 3308 曲库执行删除。

1. 上传两份项目生成的两秒测试音 A、B。
2. 删除 A：返回 204，音频读取返回 404，再删相同 ID 或未知 ID 返回 404。
3. 文件数从 2 变为 1；B 仍可读取且 SHA-256 与原测试音一致。
4. 以 Windows 文件句柄占用 B 后请求删除：返回 409、`DELETE_FAILED`；B 在列表中恢复、音频文件保留。
5. 在测试库构造两条未完成状态：B 的文件仍存在，另一条记录对应的文件不存在。
6. 实际重启测试后端：B 恢复为可见状态，缺失文件的待完成记录被清理。数据库只剩 B，deleting=0，音频哈希不变。
7. 日常曲库迁移 V2 前后，所有歌曲 ID、标题、原文件名、大小和 UTC 上传时间均保持一致。

基础接口测试脚本为 `scripts/verify-single-delete.mjs`，要求全新空测试库，并固定使用 127.0.0.1:18080。
