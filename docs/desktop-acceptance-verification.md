- 使用本机 MySQL 8.4 隔离实例（13308），源库和恢复库各有独立数据库及音乐目录。前端与后端均使用本机测试端口。

## NS-02 · 备份恢复演练

1. 暂停隔离后端写入，用 `mysqldump` 导出源库，逐一复制四份 UUID 音频文件并核对 SHA-256。
2. 将 SQL 和备份音频分别导入另一套空数据库和音乐目录，再启动恢复后端。
3. 核对四条记录的 ID、元数据、收藏、封面和音乐文件。恢复前后记录一致，音频与封面的 SHA-256 相同。四首歌的完整音频和 `206` 分段读取均正常。
4. 在恢复网页打开「我喜欢的音乐」并播放曲目 1。封面正常加载，音频在浏览器实际解码，播放进度持续前进。

本次测试备份和核对清单保存在项目的 `.local/desktop-acceptance-20261108/backup/`。

## NS-03 · 数据库故障注入

| 场景 | 结果 |
| --- | --- |
| 上传事务回滚 | 在隔离源库用临时触发器拒绝封面写入。歌曲记录先写入事务，封面插入被 MySQL 拒绝后，接口返回 `500 UPLOAD_FAILED`。歌曲记录回滚，本次上传音频被清理，原曲库记录及文件摘要一致。移除触发器后重试成功。 |
| 收藏更新时断开连接 | 持有目标行的锁，从 MySQL 锁等待表确认阻塞中的应用连接，再对该连接执行 `KILL CONNECTION`。接口返回 `500 FAVORITE_SAVE_FAILED`，收藏、音频和封面与故障前一致。释放测试锁后，连接池恢复，同一收藏操作可重试。 |
| 故障后重启 | 重启隔离源后端。五条记录、全部音频文件及封面摘要与故障前快照一致，分段读取正常。 |
