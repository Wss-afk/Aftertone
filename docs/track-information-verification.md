# 操作菜单与歌曲信息验收

日期：2026-11-06，Europe/Madrid。

## 已实现

- 每首歌曲的“…”菜单包含“修改信息”和“删除歌曲”。点击菜单不触发播放；删除继续进入原确认框，测试网页只验证取消。
- 菜单支持方向键、Home/End、Esc、Tab、点击外部关闭，关闭或打开弹窗后正确处理焦点。保存和删除期间禁用操作。
- 列表和播放器显示独立的歌名、歌手。无歌手时显示“未知歌手”，原文件名仍保存在记录中。
- 修改框可同时编辑歌名与歌手。两者去掉首尾空白，歌名不能为空；歌手可留空，均最多 255 个 Unicode 字符且不含内部控制字符。
- Flyway V3 给已有表新增 artist，旧记录默认为空，不改写标题或音频。
- 新上传从原音频读取内嵌标题、歌手，标签存在时优先采用。转码后的播放文件即使不保留源标签，数据库仍保留这些信息。标签不可读不阻断合法 MP3 上传；容量不足和中断仍按原保护处理。

## 自动化

后端 52 项、前端 38 项测试全部通过，失败、错误及跳过均为 0；TypeScript 和 Vite 生产构建通过。本轮没有增加运行依赖。

新增覆盖菜单入口与事件隔离、外部点击/键盘关闭、修改歌手及播放器同步、清空/无效歌手、旧标题请求保留歌手，以及带标签 MP3、FLAC、M4A 的实际识别与转码。

## 隔离实际验收

使用既有专用测试库及音乐目录，后端 18080、网页代理 15173。脚本为 `scripts/verify-track-information.mjs`，使用 `.local/metadata-verification/tagged-source.m4a` 生成音频，不连接日常入口。

1. 已有测试记录经 V3 迁移后返回字符串 artist，原数据仍可读取。
2. 将带“自动标签曲目 🎵 / 标签歌手”的 M4A 以 `.mp3` 文件名上传，返回 201。实际转码后的大小正确，数据库保留两项标签。
3. 直连和代理都能修改两字段；超长/控制字符歌手返回 `400 INVALID_ARTIST`。省略 artist 保留原值，空字符串清空。
4. 实际网页播放时，菜单删除项进入确认框，取消后歌曲继续播放；修改信息后列表和播放器同步更新。音源保持 `/api/v1/tracks/7/audio`，保存前后进度从 0.817643 秒继续到 1.130425 秒，paused 均为 false。
5. 后端保存完整歌手字段并立即重新读取确认，再重启隔离后端；歌曲“菜单验证音 · 已修改 / 网页测试歌手”与快照一致。其他记录、文件 SHA-256、字节数、上传时间与列表顺序保持不变。
6. 重启后完整音频返回 200，代理首段返回 206 和 1024 字节。

## 日常页面

确认当前曲库显示 Cloud / Galdive，另一首歌缺少歌手时显示“未知歌手”。“…”菜单两项可见，Esc 关闭并返回触发按钮；修改框预填独立字段，取消后保留数据。原有两首歌曲的 ID、音频哈希、原文件名、上传时间和顺序与更新前一致；当前标题和歌手以用户编辑后的值为准。
